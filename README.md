# 指尖花 · Fingertip Bloom

用摄像头识别手部骨骼，**握拳收成花苞、张开手掌让粒子花绽放**。
纯前端实现，不需要装任何插件，模型和运行时都在本地 `vendor/` 里。

> **线上版（推荐发给朋友）：https://ts-jj.github.io/fingertip-bloom/**
> 线上是 HTTPS，**手机上也能用摄像头做手势识别**，不用装任何东西，点开就能玩。
> 仓库地址：https://github.com/TS-jj/fingertip-bloom

---

## 怎么打开（重要）

**Windows：双击 `启动花朵.vbs`**

没有黑窗口，会自动起本地服务并打开浏览器访问 `http://127.0.0.1:8899/`。
浏览器询问摄像头权限时点「允许」。

> 如果 `.vbs` 被安全软件拦了，就双击 `start.bat`，效果一样，只是会留一个命令行窗口。

> ⚠️ **不要直接双击 `index.html`。**
> 浏览器**硬性禁止** `file://` 页面调用摄像头（Chrome / Edge 都一样，改代码绕不过去），
> 页面会降级成「鼠标模式」。你看到「双击启动花朵.vbs 即可」就是这个原因。

手动启动（任意系统）：

```bash
python serve.py          # 默认 8899，被占用会自动往后找端口
python serve.py 9000     # 指定端口
```

启动后窗口里会同时打印两个地址：

```
电脑打开：  http://127.0.0.1:8899/
手机打开：  http://192.168.x.x:8899/
```

## 手机上怎么看

### 方式一：直接开线上版（推荐）

**https://ts-jj.github.io/fingertip-bloom/**

HTTPS 站点，手机上**摄像头手势识别可以直接用**，不用装任何东西。
发给朋友也只发这一个链接就行。

**首次打开会在后台下载约 9MB 的模型**（wasm 2.9MB + 模型 5.9MB，都是 gzip 后的实际传输量）。
页面不会等它：打开后立刻先进花朵效果，先用手指上下滑动就能玩；模型准备好后才请求摄像头、
自动切回手势控制。下载完会缓存在浏览器里，再打开就秒开。

为缩短首次等待，页面 `<head>` 里提前 `modulepreload` 运行时、`preload` 模型文件，
避免等 90KB 页面脚本解析和粒子初始化结束才发起模型下载。

### 方式二：局域网（离线，但手机没有摄像头）

1. 手机和电脑**连同一个 WiFi**
2. 手机浏览器打开启动窗口里那个 `http://192.168.x.x:8899/`
3. 第一次连不上，多半是 Windows 防火墙拦了 —— 弹提示时点「允许访问」，
   或者到「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里放行 Python

> 电脑上打开页面时，启动页底部也会直接显示这个手机地址，不用去翻命令行。

> ⚠️ **局域网方式下手机上摄像头用不了，这是浏览器的安全限制，不是 bug。**
> 摄像头 API 只在 **HTTPS** 或 **localhost** 下才存在。手机访问的 `192.168.x.x`
> 既不是 HTTPS 也不是 localhost，所以浏览器干脆不提供 `getUserMedia`。
> 这种方式下会自动切到「手指滑动」模式 —— 上下滑动屏幕控制花朵开合，其余功能全都正常。
> 想要手机摄像头就用上面的线上版。

## 更新线上版本

线上是从 `deploy/` 目录推上去的，改了代码之后同步一下：

```bash
cp index.html bloom.mp3 ../deploy/
cd ../deploy
git add -A && git commit -m "更新"
git push
```

GitHub Pages 会自动重新构建，等半分钟左右刷新即可。

> ⚠️ **换背景音乐时注意缓存**：`bloom.mp3` 这个文件名没变的话，浏览器和 CDN
> 会继续放旧的。所以 `index.html` 里的引用带了版本号：
> ```html
> <audio id="bgm" src="./bloom.mp3?v=2" loop preload="auto"></audio>
> ```
> 每次换音乐把 `v=2` 改成 `v=3`、`v=4`…… 就行。

## 怎么玩

| 动作 | 效果 |
|---|---|
| 张开手掌 | 花瓣完全绽放 |
| 握拳 / 收拢手指 | 收成花苞 |
| 手半开 | 花朵半开，跟随开合程度连续变化 |
| 手左右移动 | 花朵视差微移，有空间纵深感 |
| 手离开画面 | 缓慢回到花苞 |

- 左下角 **「音乐」**：背景音乐开关（默认播放，点击暂停 / 再点继续）
- 左下角 **「换色」**：点一下立刻切下一个颜色；**不点也会每 9.5 秒自动换**。
  按钮前面那个小圆点就是当前花色
- 左下角 **「保存」**：把当前画面存成图片（**不含界面元素**，是纯画作，方便分享）
  - **电脑上**：点一下直接下载 PNG
  - **手机上**：会弹出一张大图，**长按图片 → 选「保存到相册」**（iPhone / 安卓 / 微信里都适用）
- 左下角 **「鼠标模式」**：没有摄像头时，鼠标上下移动（手机上滑动手指）也能控制花开
- 右下角 **HAND TRACKING**：实时预览，粉色线是识别到的手部骨骼
- 换色循环：蓝紫 → 紫 → 粉 → 蜜桃 → 橙金，背景光晕跟着一起变

> 指针移到左下角按钮上时不会影响花朵开合，可以放心点。

### 手机上

| 动作 | 效果 |
|---|---|
| 手指上滑 | 花朵绽放 |
| 手指下滑 | 收成花苞 |
| 点「换色」 | 立刻换一个颜色 |
| 点「保存」 | 弹出大图，长按存到相册 |

手机上的界面会自动精简：

- 「鼠标模式」按钮不显示 —— 手机上本来就只有手指这一种输入，没有可切换的东西
- 「全屏」按钮在 iPhone 上不显示 —— iOS Safari 至今不支持 Fullscreen API，点了也没反应
- 横屏时手势提示会移到按钮上方，花朵也会自动放大一档（横屏高度只有 390，不放大花朵太小）
- 窄屏（360 / 375 宽）按钮会自动收紧，不会贴到屏幕边缘

## 技术要点

- **渲染**：原生 WebGL 点精灵 + 加法混合，约 11.6 万粒子，单次 draw call。
  收拢/绽放两套顶点坐标存在 buffer 里，由顶点着色器 `mix` 插值，
  每个粒子带随机 `delay`，形成先后绽放的层次。
- **花朵建模**：每片花瓣是一条 Catmull-Rom 曲线（花心 → 肩部最高 → 瓣尖微扬），
  横向宽度按「纺锤形」变化（瓣根窄 → 中部最宽 → 瓣尖收尖），
  再按当前半径自适应、且宽度乘 1.34 让相邻花瓣互相叠压，从中心到瓣尖拼满一圈；
  粒子沿「丝」排列（固定横向偏移、沿花瓣长度采样），形成丝缕质感。
- **层叠**：三层花瓣（9 / 9 / 7 片）逐层错开半瓣，且每层整体抬高
  （`lift` 0 / 0.055 / 0.105，越靠瓣尖抬得越多）——这样内层花瓣从外层里"探出来"，
  花心隆起，是真正的层层叠压而不是三个同心环。这是"饱满"的关键。
- **立体感**：每片花瓣按朝向做「假光照」（左上方来光），一侧亮一侧暗，
  整朵花才有体积而不像纸片。
- **相机**：顶点着色器里做 38° 俯视投影 + 弱透视（`1/(1+z*0.28)`），
  让扁平花盘正对屏幕又保留纵深，不会前后花瓣糊成一团。
- **后处理**：场景 → 亮部提取（1/4 分辨率）→ 两轮分离式高斯模糊 → 合成。
  合成时做 ACES 色调映射、镜头色差、暗角、胶片颗粒，加法混合的高光不会爆白。
- **换色**：顶点着色器里做 HSL 色相旋转。关键技巧是**先把颜色归一化到最大通道为 1**
  再转 HSL，这样亮度和色相解耦，暗部粒子不会因为饱和度计算失真而变灰。
  花心单独只转 22%，保持暖色。
- **手势**：MediaPipe HandLandmarker 取 21 个关键点，
  开合度 = 五个指尖到腕点距离均值 ÷ 掌长，实测区间 `1.02 → 1.58` 映射到 `0 → 1`，
  再做帧率无关的指数平滑。
- **动画**：入场从中心一点逐粒萌发（`intro`）；花心缓慢搏动、花粉向上飘散；
  整朵花被「微风」轻吹（瓣尖摆幅更大）；开合变化时轻轻震颤（`pulse`）；UI 错落入场。
- **音乐驱动**：`AnalyserNode` 读低频（约 40–520Hz），用「慢速基线」提取鼓点 ——
  持续的低音被 1.2 秒时间常数的基线吸收，只有突然变强才算一拍。
  这一拍驱动整朵花轻微胀缩、花心搏动加强、辉光增强。
- **落瓣**：520 个粒子分布在最外层花瓣上，各自带随机相位缓慢脱离、飘落、淡出，
  形成持续的花瓣雨；花苞状态下自动隐藏。
- **绽放光爆**：开合度越过 0.88 的瞬间触发一次约 1 秒的光爆 ——
  从花心向外扩散一圈光环 + 辉光增强 + 花粉外扩，把「到达」变成「高潮」。
- **保存图片**：WebGL context 开了 `preserveDrawingBuffer`，
  在渲染完的那一帧直接 `toDataURL`，存下来的只有画面、没有 UI。
  ⚠️ **手机上 `<a download>` 是不可用的**，所以走了完全不同的路：
  1. iOS Safari 对 `data:` URL 的 `download` 属性**直接忽略**，点了毫无反应；
     微信内置浏览器干脆禁下载。唯一全平台通用的做法是**长按图片存相册**。
  2. 所以手机端点保存后弹出一张全屏大图，提示「长按 → 保存到相册」。
     关键细节：`<img>` 上**绝不能**写 `-webkit-touch-callout:none` / `user-select:none`，
     否则系统菜单根本呼不出来。
  3. **格式必须用 JPEG**：这张图全是高频粒子 + 胶片颗粒，PNG 压不动 ——
     780×1688 的 PNG 转 base64 有 **4MB**，iOS 的 `<img>` 处理这么大的 data URL 会渲染失败，
     长按也存不下来。JPEG 0.94 只有 **500KB**，肉眼几乎看不出差别。
     桌面端仍然给无损 PNG。
  4. 导出前把最长边压到 2048，避免 iPad 这类高分辨率设备生成超大图。
- **音乐**：`<audio loop>` + 2.2 秒淡入。浏览器自动播放策略要求用户交互，
  所以挂在遮罩按钮点击 / 任意 pointerdown 上补播，不会静默失败。
  ⚠️ 这里有两个**很容易把声音搞没**的坑（已修）：
  1. `createMediaElementSource()` 一旦接管，音频输出就走 AudioContext 了。
     如果此刻 AudioContext 拿不到 `running` 状态，声音会**彻底消失**，连 `bgm.play()` 都救不回来。
     所以建图前必须 `await ctx.resume()` 并检查 `ctx.state === 'running'`，
     拿不到就 `close()` 掉、**放弃接管**，老老实实走 `<audio>` 直出。
  2. 接管之后 `audio.volume` **完全失效**，淡入淡出会变成空操作。
     必须改用 `GainNode` 控音量（`setVolume` / `getVolume` 统一走它）。
  另外建图不 `await`（先出声、再慢慢接分析），最多重试 4 次，每次用户手势都补一次。
  3. 被浏览器拦下时，**光让按钮闪是不够的**——很多人根本不会注意到左下角。
     现在会在屏幕下方冒一条常驻提示「点一下屏幕，开启音乐」，点任意位置就播起来，
     播成功自动收起。iOS 的自动播放策略最严，这条提示基本是给 iPhone 用户准备的。
- **模型加载必须有超时兜底**（这条是踩过坑才加的）：
  MediaPipe 的 GPU delegate 在 **iOS Safari 上会「永久挂起」**——既不 resolve 也不 reject。
  `await` 一个永远不返回的 Promise，页面就永远停在「正在唤醒花朵」，
  用户看到的就是「点开一直不动」。三层防护：
  1. `import()` / `build()` 每个 await 都包 `withTimeout()`，超时就当失败继续往下走
  2. **iOS 设备直接跳过 GPU**，只用 CPU delegate（手机上跑 640×480 完全够用）
  3. 加载页显示秒数，**8 秒后出现「跳过，先看效果」**，随时能进手指滑动模式
- **降级**：模型加载失败 / 摄像头被拒 / `file://` / 非 HTTPS 的局域网访问，
  全部自动切鼠标模式，不会白屏；摄像头被拒时提供「重新尝试摄像头」按钮。
- **自适应画质**：粒子大小按屏幕密度自动收放（`uPxK`，小屏上粒子不会糊成一团）；
  连续 100 帧低于约 28fps 先把渲染分辨率降到 1x，还卡就把粒子抽稀到 62%
  （粒子顺序在构建时已打乱，抽稀是均匀抽样，不会缺掉整片花瓣）。
  点「保存」时会**临时把分辨率和粒子数拉满**再截图，所以降级状态下存出来的图依然是高清的，
  截完 320ms 后自动还原（`qualityLock` 防止刚提上来又被自适应逻辑降回去）。
- **手机适配**：
  - 触屏判定 `pointer:coarse` + `maxTouchPoints`，文案、保存方式、按钮显隐都走这个分支
  - 横屏手机（高度 < 560）单独放大花朵一档，否则按桌面系数算只有屏高的一半
  - 窄屏（< 380）按钮收紧 padding 和字号，避免 5 个按钮贴到右边缘
  - 摄像头预览在手机上 **164×123（严格 4:3）**，和视频源同比例，
    既不会把脸压扁，也不会小到看不清；窄屏（< 380）再收到 148×111
  - 摄像头面板默认 `display:none`，只有真正拿到画面才 `display:block` ——
    否则降级后会留一个空黑框（原来的 `classList.remove('on')` 在 CSS 里根本没有对应规则）

## 调参位置（`index.html`）

| 想改什么 | 找哪里 |
|---|---|
| 花朵大小 | `pxPerUnit = Math.min(W, H) * ...` |
| 花瓣形状 / 花盘深浅 | `const PATH = [...]` 六个控制点 |
| 花瓣数量 / 密度 | `const LAYERS = [...]` |
| 花瓣宽度轮廓 | `petalOpen()` 里的 `bell` / `shape` |
| 花瓣明暗 / 立体感 | `petalColor()` 里的 `lit` |
| 配色 | `petalColor()` + `HUE_SEQ`（换色序列，改这里就能加自己的颜色） |
| 换色速度 | `state.hueTimer > 9.5`（自动间隔）+ `dt * 1.8`（过渡快慢） |
| 落瓣数量 / 速度 | `CUR_KIND = 3` 那段循环 + 顶点着色器里的 `uTime * 0.052` |
| 光爆强度 | 合成着色器 `ring * uBurst * 0.50` |
| 音乐灵敏度 | `readBass()` 里的 `* 5.5` |
| 相机俯角 | 顶点着色器 `float ang = -0.66;` |
| 花朵大小（竖屏 / 横屏手机 / 桌面） | `pxPerUnit` 那行的 `0.375 / 0.36 / 0.30` |
| 辉光强度 | `uThreshold` / `uGlowAmt` / `aces(col * 3.00)` |
| 灵敏度 | `handOpenness()` 里的 `1.02 / 1.58` |
| 摄像头预览大小 | `.cam` 的 `width` / `height`（手机在 `@media (max-width:820px)` 里） |
| 模型加载超时 | `loadModel()` 里 `plan` 数组的毫秒数（GPU 13s / CPU 34s） |
| 「跳过」几秒后出现 | `boot()` 里的 `s >= 8` |
| 音乐提示条位置 | `.mtip` 的 `bottom`（手机在 `@media (max-width:820px)` 里是 176px） |
| 音量 | `MUSIC_VOL` |
| 保存图格式 / 质量 | `takeShot()` 里的 `toDataURL('image/jpeg', 0.94)` |
| 保存图最大边 | `takeShot()` 里的 `MAXEDGE = 2048` |
